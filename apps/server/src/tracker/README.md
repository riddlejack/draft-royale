# Game tracker setup

The tracker stores public Clash observations by normalized player tag, independently of Draft Royale accounts. Account-to-tag links are versioned so changing a linked tag does not rewrite old battle identity. Duplicate account subscriptions share one adaptive polling schedule; manual tallies remain creator-owned.

The tracker stores only observations it has actually received. Clash Royale's battle-log endpoint is a recent rolling window, so this is not guaranteed to reconstruct games from before the tracker started or long periods while the server was offline.

Set `CLASH_ROYALE_API_TOKEN` in the server process environment. The token is used only by the backend and is never returned by a tracker route or requested by the browser. By default the server calls `https://proxy.royaleapi.dev/v1`; `CLASH_ROYALE_API_BASE_URL` can override that base for a compatible service.

For a source-checkout installation, place `CLASH_ROYALE_API_TOKEN=your-key` in `data/private/tracker.env` (ignored by Git) and restrict that file to your user with `chmod 600 data/private/tracker.env`. `DRAFT_ROYALE_TRACKER_ENV_PATH` can point the server at a separate persistent secret file. The packaged host service uses that override with `/path/to/DraftRoyale/config/tracker.env`, so a release update never replaces the key. Restart that service with `sudo launchctl kickstart -k system/com.example.draftroyale.server`. Keep the key out of chat and source control.

Observed games remain in SQLite across restarts; aggregate records use the same selected date, mode, player, and relationship filters as recent history. Exact own decks, opposing cards/decks, and exact deck matchups retain sample counts and W/L/D/unknown results. Duel payload rows are labeled and counted as rounds rather than silently treated as series outcomes. Back up the SQLite database when moving hosting, including accounts, decks, rooms, and game history together.

For the RoyaleAPI proxy, create the key following <https://docs.royaleapi.com/proxy.html> and whitelist `45.79.218.79` as the documented proxy address. Do not commit the token.

Without a token, authenticated users get a truthful `missing_token` status, saved/imported history, and a working manual tally. The backend polls each distinct tag at adaptive bounded quick/idle intervals, de-duplicates the same battle across player perspectives, uses per-tag jitter and Retry-After/error backoff, times out stalled requests, bounds raw-response and attempt retention, and cancels active requests when it closes. Non-overlapping rolling windows are reported as possible gaps; they are not treated as proof that no games occurred.

See [`docs/tracker-history-import.md`](../../../../docs/tracker-history-import.md) for the schema-limited, backup-first historical import flow and personal-data-export prerequisite.

## Full battle detail, deck log, and counter audit

- Every API battle keeps its raw record in `tracker_battle_raw` (icon URLs removed, roughly 4 KB each), and `tracker_battles` / `tracker_participants` carry `deckSelection`, arena, league, trophies, tower hit points, clan, card levels and tower troops. Rows recorded before this (`detail_version = 0`) are upgraded in place the next time the API reports the same battle, so the first poll after an upgrade recovers whatever is still in each tag's rolling window.
- `GET /api/tracker/decks?playerTag=` returns every distinct eight-card deck a visible player has used, with record, modes, and first/last use. `deckSelection` separates decks the player chose (`collection`, war picks) from decks a mode assigned (`predefined` mirror decks, `draft`, `pick`, event decks). Older rows fall back to the mode name and are marked `originInferred`. Duel battles list every round's cards together and are skipped until rounds are parsed from the raw record.
- The player profile is snapshotted into `tracker_profile_snapshots` whenever new battles arrive and every six hours when idle. `GET /api/tracker/battle-count-audit?playerTag=` compares the `battleCount` delta with recorded battles by type, which shows which battle types the lifetime counter includes and whether any battles were missed.
- Published library decks are shared with the viewer's accepted friends only (`GET /api/decks/community` requires sign-in).

## Insights, card stats, and deck record

All three routes are authenticated and scoped to the viewer plus accepted friends. A `playerTag` outside that scope falls back to the viewer's own tag, and a `rivalTag` outside it (or equal to the player) is dropped. The analytics are pure functions over `TrackerBattle[]` in `insights.ts`; the service loads only the focus player's battles.

- `GET /api/tracker/insights?playerTag=&rivalTag=&mode=&dateFrom=&dateTo=&includeAssigned=1&tzOffsetMinutes=` returns `{ insights }`. `mode` and the inclusive UTC `dateFrom`/`dateTo` days match `/summary`. `tzOffsetMinutes` (integer, -840 to 840, minutes added to UTC) sets the local hour, weekday and month buckets; anything else is a 400.
- Two samples are reported and every rate carries its games, wins, losses and draws. `sample` is every filtered battle and feeds the trophy timeline, tilt, time of day and rivalries. `baseline` is the deck-skill sample: non-duel battles with an eight-card deck the player built. It feeds card insights, level gap, elixir leaked and matchups. `includeAssigned=1` adds mirror, draft, pick and event decks to it. Rivalry results always count every deck origin, with `versusChosen` and `versusAssigned` kept apart; only the deck and card lists inside a rivalry follow `includeAssigned`.
- Card insights give the record with a card, the record against it (once per battle, even when both 2v2 opponents hold it) and the difference from the baseline win rate. `blindSpots` and `strengths` need five decided games against the card and are ordered by the Wilson 95% bound nearest the baseline (upper bound for blind spots, lower for strengths), so a long record outranks a lopsided handful. The interval is returned for the UI to show.
- Tilt builds sessions (a gap over 30 minutes starts a new one) from all of the player's battles, so a mode filter still sees the losses that came before; only filtered battles are tallied. Level gap and elixir leaked are 1v1 only, and level gap needs levels on all sixteen cards. Matchups group opposing decks by average elixir (decks with an unknown cost are skipped) and by tower troop, without guessing archetypes.
- `GET /api/tracker/card-stats?playerTag=` returns `{ cardStats }` for the deck builder: chosen decks only, one entry per card id across forms (tallied by id, not summed from forms) with a per-form breakdown and the baseline.
- `GET /api/tracker/deck-record?playerTag=&cards=` takes exactly eight distinct positive card ids separated by commas (else 400 `INVALID_INPUT`) and returns `{ deckRecord }`: the chosen and assigned records of that card set ignoring forms and order, plus its five most recent battles.
